AI开发实习生远程作业：AI圆桌讨论 Web App MVP
1. 背景与业务需求
1.1 产品定位
「AI Panel Studio」是一款"AI 圆桌讨论"本地 Web 应用：用户输入任意讨论话题并指定参会专家人数（默认4人），系统调用大模型动态生成一组主持人与嘉宾，展示每位嘉宾的姓名、职业、Title、立场与专属颜色标识；用户确认阵容后进入演播厅观看模拟对话。现场由 AI 主持，实时推出的圆桌讨论。
核心价值观主张：让任何人都能随时召集一支“虚拟智囊团”，围绕任意议题展开深度碰撞——主持人负责开场、追问、串联与收尾，专家之间自主“举手/抢答/补充/反驳”，讨论过程中持续生成共识与分歧，最终呈现一场沉浸式的 AI 圆桌实况。
1.2 目标用户画像
用户群体	特征描述	核心诉求	
知识工作者与研究人员	需要快速对一个议题进行多角度审视，时间有限	在几分钟内获得来自不同角度的深度分析与争辩摘要	
产品/决策人员	在方案评审或战略讨论前希望预演各方立场与潜在争议	用 AI 圆桌发现盲点、检验假设，提升决策质量	
教育与内容创作者	需要将复杂议题结构化呈现给受众，追求沉浸感与叙事性	获得一场可录制、可回放的“虚拟专家访谈”作为内容素材	
1.3 用户痛点分析
视角单一：使用单一 AI 对话获得的分析往往立场单一，缺乏真实辩论中“对抗性思考”所带来的深度
异步割裂：多轮次轮询不同视角的 AI，上下文割裂，观点之间无法真正产生互动与碰撞
过程不可见：AI 输出通常只是终结呈现，缺乏“思考过程”和“观点演化”的实时感与沉浸感
议题管理混乱：用户希望同时探索多个议题，但不同讨论的上下文、进展与结论难以并行隔离管理
1.4 作业要求
本次作业要求你使用 任意Vibe Coding 工具，从 0 到 1 一人完成一个极简但有生产级质感的 AI 圆桌演播厅 MVP，具体产品能力要求如下：
功能要求：
首页：展示当前所有正在进行的讨论列表；用户可加入/观察已有讨论，也可发起新讨论。
嘉宾生成：用户输入话题与专家人数后，系统调用大模型动态生成主持人 + 专家阵容，展示姓名、职业/Title、立场、专属颜色标识，由用户确认后进入演播厅。
演播厅模式：主持人负责开场、追问、串联和总结；专家根据当前 transcript 自主决定发言顺序（举手/抢答/补充/反驳），每次发言控制在 1~2 句；不允许机械式轮流发言。
专家状态小窗：每位专家有独立小窗，实时显示 Agent 运行状态（待机/准备发言/发言中）、当前关注点或公开思考摘要；不展示真实的隐藏 chain-of-thought。
实时共识与分歧：讨论过程中持续从发言中提炼共识与分歧，实时更新对应区域，不等到讨论结束后才生成。
现场 Transcript：显示发言人姓名与职业/Title，用与专家一致的颜色区分；不显示“举手”等内部事件。
总结：结束时主持人以自然语言进行总结，禁止将 JSON 原文显示到页面上。
技术要求：
可本地运行的前后端分离项目；大模型 API Key 只能放在后端从环境变量读取，不得暴露到浏览器端。
支持多个讨论并行；不同讨论的状态、事件流、transcript、共识与分歧必须相互隔离。
实时更新使用 SSE、WebSocket 或事件机制。
页面为中文 UI，响应式布局：不依赖整个页面滚动，各区域在自身容器内独立滚动；超宽屏、普通桌面与窄屏均需合理分配区域。
核心考察点：
考察候选人如何在不同阶段合理应用不同的开发范式，以有效管理 AI 上下文，避免大模型幻觉。
基于业务需求，驱动数据建模（讨论、嘉宾、发言、共识/分歧等实体）与 API 契约的精确定义。
以演播厅现场氛围与交互设计要素为驱动构建前端组件与状态流转。
针对核心逻辑（嘉宾生成、发言调度、共识提炼）严格遵循测试驱动工作流，并包含完整的端到端（E2E）测试。
考察你对 Prompt 的结构化表达能力，以及如何引导 AI 解决具体问题。
对“AI 圆桌演播厅”沉浸感与实时性的理解与功能落地，UI 是否真的像在观看一场演播厅讨论。
