## 1.【SDD 阶段】数据模型与 API 契约

**对应提交**：`beedbe1 sdd: 数据模型、Pydantic契约与初始化脚本`、`5a1f013 docs: 需求文档、PRD与API契约（SDD阶段）`

**当时的指令（要点）**
> “先把数据模型与接口契约定下来：会话 / 席位 / 发言 / 共识四张表，字段要能支撑直播 + 回看；
> 用 Pydantic 定义 REST 出入参与 SSE 事件，契约即前后端唯一真源；再写初始化脚本与样例数据。”

**背景 / 挑战 / 引导修正**
- 背景：前端要先开工，但接口字段还在改，容易出现“两套契约”。
- 挑战：AI 初版把 SSE 事件字段写成了“前端展示字段 + 事件字段”两套，且事件类型只列了 3 种。
- 引导：要求“所有事件共用一个信封（`session_id` / `seq` / `ts` / `data`），事件类型必须覆盖
  真实链路需要的全部事件”，并把 `seq` 同时作为 SSE `id:` 支撑 `Last-Event-ID` 重连；契约里
  禁止出现前端命名（如 `avatarColor`），颜色一律 `#RRGGBB`。

**产物**：`backend/models.py`、`backend/schemas.py`、`docs/API.md`、`docs/ER.md`

## 2.【SDD 阶段】数据库 ER 图与约束设计

**对应提交**：`beedbe1 sdd: 数据模型、Pydantic契约与初始化脚本`

**当时的指令（要点）**
> “用 mermaid 画 ER 图，并把每条约束写清楚：同场配色唯一、同场姓名唯一、`round` 同场唯一、
> `expert_ids` 只能属于本场；同时说明为什么主持人也要落库。”

**背景 / 挑战 / 引导修正**
- 背景：回放要保证“看到的 = 存的”，需要数据库层给出幂等键。
- 挑战：AI 初版把 `round` 当成“轮次”而非“同场发言序号”，并且没有约束“同场颜色唯一”。
- 引导：明确 `round` 是发言序号（唯一键，用于 SSE 与拉取去重）、颜色必须由服务端调色板分配并加
  `uq_experts_session_color`；把“为什么主持人也落库”写成设计说明，避免后续为此拆表。

**产物**：`docs/ER.md`（mermaid `erDiagram` + 表结构明细 + 多场隔离规则）

## 3.【DDD 阶段】前端组件与页面生成

**对应提交**：`4cc8b36 ui: 首页与演播厅页面搭建（DDD阶段）`、`84c2b38 components: 专家卡片/发言气泡/状态小窗/共识面板`

**当时的指令（要点）**
> “按领域拆分组件：首页负责列表 + 发起讨论，阵容确认页只做确认门，演播厅负责实时流；
> 专家卡片、发言气泡、状态区、共识面板、阶段条各自独立；所有颜色读后端字段，前端不许自行取色。”

**背景 / 挑战 / 引导修正**
- 背景：页面先做出来才能验证 SSE 数据是否够用。
- 挑战：AI 初版把“举手 / 抢答 / 调度”等内部字段也渲染进了气泡，还把主持人做成一张独占大卡。
- 引导：要求“Transcript 只渲染 `姓名 + 职业/Title + 正文`”，内部事件一律不上屏；主持人
  必须与专家同一套卡片、同一尺寸；三档响应式采用容器内滚动（`html/body` 永不滚动）。

**产物**：`frontend/src/views/{Home,Lineup,Studio}.vue`、`frontend/src/components/*.vue`

## 4.【DDD 阶段】五大流程 Prompt 设计

**对应提交**：`89b82fd ddd: 五大流程Prompt设计`

**当时的指令（要点）**
> “把阵容生成、举手调度、发言、共识提炼、总结五个流程的 Prompt 集中管理，统一三段式结构
> （角色设定 → 任务说明 → 输出格式约束）；Prompt 里不放运行时数据，议题与席位由 user message 给。”

**背景 / 挑战 / 引导修正**
- 背景：模型输出必须能直接上屏，不能出现 JSON 或“首先/其次”。
- 挑战：AI 初版把议题直接写进系统 Prompt（`根据议题 {topic}`），导致占位符永远不被替换；
  总结还要求模型直接输出三段结构化字段。
- 引导：系统 Prompt 只沉淀“不随请求变化”的规则；总结只要求自然语言正文，三段由服务端按空行切分；
  后来专门修掉了字面 `{topic}` 占位符（提交 `7179944`）。

**产物**：`backend/flows/prompts.py`、`backend/flows/summary.py`（`split_summary_sections`）

## 5.【TDD 阶段】测试用例编写与实现

**对应提交**：`be49125 tests: pytest测试用例（TDD阶段）`

**当时的指令（要点）**
> “先写测试再写实现：路由、流程、调度、SSE 都要有可断言的用例；测试必须能零网络、零等待运行，
> 用 Mock 模式与注入的随机种子保证可复现。”

**背景 / 挑战 / 引导修正**
- 背景：没有测试时，改一处发言逻辑就会悄悄破坏另一条链路。
- 挑战：AI 初版用例依赖真实时钟（`sleep`）与随机顺序，导致偶发失败；断言只覆盖“有没有”，
  不覆盖“顺序 / 归属”。
- 引导：要求测试内把 `SPEAK/THINK/TYPING` 间隔压到 0、调度注入 `random.Random(seed)`；
  对 SSE 断言 `seq` 连续、事件顺序与归属；对数据库断言落库条数与事件一致。

**产物**：`backend/tests/`（`conftest.py`、`test_routers.py`、`test_flows.py`、`test_turn_taking.py` 等）

## 6.【TDD 阶段】发言质量修复（议题贴合 / 均衡轮转 / 实时性）

**对应提交**：`a5e1c4e fix: 发言贴合议题、均衡轮转防扎堆、正在发言态、专家状态栏统一`、`7179944 fix: LLM重试降级与超时生效…`

**当时的指令（要点）**
> “MOCK 发言要贴合议题、不能串题；同一人不能连说、有人不能全程沉默；反驳要指名道姓且不复读；
> 讨论中要有 typing 状态；专家状态栏主持人与专家必须一致。”

**背景 / 挑战 / 引导修正**
- 背景：换议题后仍念“手机/67%”等旧素材，观众一眼看出内容与议题无关。
- 挑战：素材写死在域表里、调度随机导致扎堆、反驳直接复述对方整句。
- 引导：把素材改成“议题域机制 + 场景锚点”，所有句式带 `{keyword}` 槽位；新增均衡轮转排期
  （每轮全员各一次）；反驳改为只复述 ≤10 字关键判断词；补测试逐条守住这些约束（本轮又补上
  “共识实时推送”“焦点字段下发”“并行互不串扰”断言）。

**产物**：`backend/arguments.py`、`backend/flows/scheduling.py`、`backend/tests/test_arguments.py`、`test_scheduling.py`

## 7.【E2E 阶段】系统级测试

**对应提交**：`af11dc0 test: E2E全链路测试 + README文档`

**当时的指令（要点）**
> “用 pytest + httpx 走真实 HTTP/SSE 路径，覆盖 创建 → 开演 → 讨论 → 结束 → 回看 → 中断恢复
> 六个场景；断言零新增 LLM 调用，并保证 30 秒内跑完。”

**背景 / 挑战 / 引导修正**
- 背景：单元测试都绿，但“刷新后是否重跑”“回看是否偷偷生成”只有端到端才能验证。
- 挑战：AI 初版用真实 `EventSource` 前端通道，测试要等真实时钟；且没有“调用记录”证明零生成。
- 引导：用 `httpx.ASGITransport` 内联 ASGI 应用（不占端口），把 `get_llm` 换成记录型客户端，
  用“调用记录为空”断言回看不生成；用清空进程内任务表 + 广播中枢模拟重启，验证断点续播。

**产物**：`backend/tests/test_e2e_flow.py`、`scripts/ui_smoke.mjs`（浏览器级冒烟）
